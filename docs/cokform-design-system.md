# 콕폼 디자인 시스템

## 1. Brand core

콕폼은 폼을 예쁘게 꾸미는 도구가 아니라, 필요한 답을 정확히 받도록 돕는 응답 경험 도구다. 모든 화면은 사용자가 다음 질문을 더 잘 만들고, 응답자가 더 편하게 답하고, 운영자가 결과를 더 빨리 이해하도록 설계한다.

> **필요한 답을, 콕 집어 받아요.**

`ASK IT WELL`은 브랜드의 보조 문구이며, 제품 곳곳에서 장식처럼 반복하지 않고 시작점·빈 상태·완료 순간처럼 브랜드 관점이 필요한 위치에만 사용한다.

## 2. Logo system

### 2.1 Symbol meaning

로고 심볼은 세 가지 형태를 결합한다. 말풍선은 질문과 응답을, 내부의 초록 점은 정확히 짚은 핵심을, 우상단의 작은 코랄 점은 다음 행동을 의미한다. 라임 바탕은 밝고 기억하기 쉬운 브랜드 신호로 사용한다.

| 자산 | 파일 | 권장 사용 |
|---|---|---|
| 기본 로고 | `public/brand/cokform-logo.svg` | 헤더, 문서, 공유 화면, 마케팅 |
| 심볼 | `public/brand/cokform-mark.svg` | 파비콘, 앱 아이콘, 작은 화면 |
| 생성 콘셉트 | `public/brand/cokform-symbol-concept-*.png` | 내부 탐색 자료. 제품 UI에는 사용하지 않음 |

### 2.2 Clear space and misuse

로고 주변에는 심볼 높이의 절반 이상을 비워 둔다. 심볼을 임의로 기울이거나, 색상을 보라색·그라디언트로 바꾸거나, 말풍선에 그림자·외곽선을 추가하거나, 워드마크와 심볼의 비율을 임의로 조정하지 않는다. 작은 크기에서는 워드마크를 제거하고 심볼만 사용한다.

## 3. Color tokens

| Token | Hex | 의미 | 사용 |
|---|---|---|---|
| Ink | `#17251F` | 질문과 응답의 중심 | 제목, 본문, 로고 |
| Cream | `#FFFDF8` | 사람을 환대하는 표면 | 카드, 헤더, 입력 배경 |
| Canvas | `#F5F3EC` | 작업 공간 | 페이지 배경, 편집 캔버스 |
| Cok Green | `#17866D` | 진행과 신뢰 | 주요 CTA, 활성 탭, 성공 |
| Green Deep | `#0B4D3D` | 강한 대비 | CTA 텍스트, 강조 |
| Lime Signal | `#D8ED59` | 콕 찍은 신호 | 심볼, 배지, 선택 포인트 |
| Coral | `#F28B70` | 주의와 인간적 온기 | 알림, 보조 강조, 작은 점 |
| Line | `#DDE1D9` | 구조를 가볍게 나눔 | 경계선, 입력 필드 |

보라색은 사용하지 않는다. 제품에서 강조색을 추가해야 한다면 기존 의미 체계와 충돌하지 않는지 먼저 검토하고 `src/theme.js`의 토큰으로 등록한다. 컴포넌트에서 색상 값을 새로 직접 만들지 않는다.

## 4. Typography

기본 서체는 Pretendard Variable이며, 폴백은 Pretendard와 Noto Sans KR이다. 제목은 짧고 강하게, 본문은 편안한 줄 간격으로 쓴다.

| 역할 | 크기 | 굵기 | 자간 | 원칙 |
|---|---:|---:|---:|---|
| Display | 36–48px | 600–700 | -0.04em | 한 화면에 하나의 질문만 둔다. |
| Page title | 24–32px | 600–700 | -0.03em | 제품 용어보다 사용자의 목적을 쓴다. |
| Section label | 11px | 700 | 0.18em | 영문 대문자, 보조 계층에만 사용한다. |
| Body | 14–16px | 400–500 | normal | 한 문장에 한 행동만 제안한다. |
| Caption | 11–13px | 400–600 | normal | 상태·시간·보조 설명에 사용한다. |

## 5. Shape and elevation

기본 카드 모서리는 18–24px, 버튼은 완전한 pill 형태, 입력 필드는 12px 이상으로 둥글게 한다. 카드에는 진한 그림자를 사용하지 않고 `Line` 경계선과 아주 약한 Ink 그림자로 깊이를 만든다. 질문·답변·운영처럼 정보 밀도가 높은 화면도 표면을 겹겹이 쌓기보다 하나의 캔버스 안에서 여백으로 계층을 구분한다.

## 6. Interaction principles

콕폼의 인터랙션은 문서 편집기의 조작감보다 응답 흐름을 만드는 감각을 제공해야 한다. 주요 행동은 초록색으로 하나만 강조하고, 보조 행동은 아이콘 버튼이나 라임 배지로 처리한다. 저장 상태는 사용자가 추측하지 않도록 `저장 중`, `저장됨`, `저장하지 못했어요`를 명시한다. 공유 완료는 `게시됨`이 아니라 `응답을 받을 준비가 됐어요`로 안내한다.

| 상태 | 사용자 문구 |
|---|---|
| 빈 폼 | 아직 만든 폼이 없어요. 위에서 하나를 골라 시작해보세요. |
| 저장 중 | 변경사항을 저장하고 있어요 |
| 저장 완료 | 저장됨 |
| 공유 준비 | 응답을 받을 준비가 됐어요 |
| 응답 완료 | 답을 잘 받았어요 |
| 오류 | 잠깐 문제가 생겼어요. 다시 시도해볼게요. |

## 7. Component rules

홈은 목적별 시작점, 템플릿, 작업 공간 순서로 보여준다. 편집기는 `흐름`, `답변`, `운영`의 세 영역을 유지하되, 질문 카드는 문서 블록이 아니라 응답 목적을 설계하는 단위로 발전시킨다. 응답자 화면은 한 번에 하나의 질문에 집중시키고, 완료 화면에서 다음 행동을 분명히 제시한다.

버튼 카피는 동작 결과를 말한다. `확인`보다 `공유 시작`, `저장`보다 `변경사항 저장`, `게시`보다 `응답 받기`를 선호한다. 아이콘만 있는 버튼에는 반드시 접근 가능한 `title` 또는 `aria-label`을 제공한다.

## 8. Asset and code conventions

브랜드 색상은 `src/theme.js`에서 관리한다. 로고는 `public/brand/`의 SVG 원본을 사용하고, 화면 안에서 로고를 다시 그리는 인라인 SVG를 만들지 않는다. 새 UI 컴포넌트는 하드코딩한 색상보다 토큰과 공통 클래스(`cok-eyebrow`, `cok-display`, `cok-button-primary`, `cok-button-soft`)를 우선한다.

배포 전에는 다음을 확인한다.

| 검증 | 기준 |
|---|---|
| 색상 | Material 보라색과 구형 회색 토큰이 남아 있지 않음 |
| 로고 | 헤더·파비콘·공유 화면의 심볼이 동일함 |
| 반응형 | 320px 모바일에서도 로고·CTA·질문 카드가 잘리지 않음 |
| 접근성 | 주요 이미지에 대체 텍스트, 아이콘 버튼에 이름이 있음 |
| 카피 | 설문지·게시·설정 등 구형 도구 언어가 목적 중심 언어로 검토됨 |
