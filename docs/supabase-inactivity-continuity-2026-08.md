## 현재 상태

Cokform Supabase 프로젝트(`bnbdxcyarerrmijuvxdb`)는 2026-08-18 기준 `ACTIVE_HEALTHY` 상태다. 리전은 서울(`ap-northeast-2`)이며, 현재 즉시 중단·삭제 상태는 아니다.

## 무료 플랜 위험

Supabase 공식 정책상 무료 플랜 프로젝트는 지난 7일간 충분한 사용자 데이터베이스 활동이 없으면 자동 일시중지 후보가 된다. 일시중지 전에 프로젝트 소유자에게 경고 메일이 발송되고, 실제 일시중지 뒤에도 확인 메일이 발송된다. 일시중지된 프로젝트는 Supabase Dashboard에서 최대 1년간 복원할 수 있으며, 복원하면 기존 데이터와 구성이 이전 상태로 돌아온다.[1]

이는 즉시 삭제가 아니라 **서비스 중단 위험**이다. 응답 링크·로그인·폼 저장이 작동하지 않을 수 있고, 작성자·응답자 모두 실패 경험을 겪는다. 1년 복원 창이 끝난 뒤에는 Supabase 플랫폼 백업에 의존할 수 없으므로, Cokform 자체의 암호화 복구 번들과 독립 백업이 계속 필요하다.

## Cokform 권고 기준

파일럿 단계에서는 무료 유지 방식을 쓰되, 매일 실제 데이터베이스에 최소 활동을 만드는 유지 요청과 실패 알림을 둔다. 이 요청은 응답 원문을 읽거나 쓰지 않고, 공개 폼 존재 여부처럼 최소한의 메타데이터만 조회해야 한다. 또한 이미 구현된 폼별 암호화 복구 번들과 암호화된 DB 백업은 유지한다.

활성 고객 폼·유료 고객·운영상 SLA 약속이 생기면 Pro 전환을 우선 검토한다. Pro는 자동 일시중지를 막지만, 개인키·복구 비밀번호를 잃은 E2EE 응답을 복원해 주지는 않으므로 작성자용 키 백업·복구 번들은 계속 필수다.

- Cokform 프로젝트는 현재 `ACTIVE_HEALTHY`다.
- 기존 `supabase-encrypted-backup.yml`은 매일 04:29 KST 실행되도록 등록돼 있으나, 실제 수동 실행에서 `SUPABASE_DB_URL GitHub Secret이 없습니다.`로 시작 단계에서 실패했다.
- 따라서 현재는 암호화 DB 백업이 생성되지 않으며, 이 워크플로가 Supabase 활동을 유지한다는 보장도 없다.
- `SUPABASE_DB_URL`과 `BACKUP_AGE_RECIPIENT`를 설정한 뒤 수동 실행 1회 성공을 확인해야 백업 보호를 활성화로 판단할 수 있다.

## 2일 주기 유지 요청 검증

`Keep Cokform Supabase active` 워크플로를 2026-08-18에 수동 실행했고 성공했다. 이 작업은 `form_public`에서 공개 폼 식별자 최대 1개만 읽고, 응답 내용·암호문·개인정보를 출력하거나 저장하지 않는다. 다음 자동 실행은 UTC 03:17(한국 시간 12:17)에 2일 주기로 동작한다.

작업이 HTTP 200 이외의 상태를 받거나 네트워크 요청에 실패하면 GitHub Actions 실행은 실패 상태로 종료된다. 운영자는 Actions의 `Keep Cokform Supabase active` 실행 결과를 확인하면 되고, GitHub 알림에서 해당 워크플로 실패 알림을 허용해 두는 것이 권장된다. 7일의 Supabase 비활성 판정 창보다 짧은 2일 간격이므로, 한 번의 예약 실행이 지연되거나 실패해도 다음 실행 전 수동 조치 여유가 있다.
