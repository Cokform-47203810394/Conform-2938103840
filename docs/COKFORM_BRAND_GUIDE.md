# Cokform 브랜드 가이드

> **원하는 대로, 콕 묻고 받아요.**

Cokform은 한국의 일하는 방식에 맞춘 폼 서비스입니다. `콕`은 귀엽게 꾸민다는 뜻이 아니라, 필요한 지점을 정확히 집어 묻고 다음 일까지 이어간다는 뜻입니다. 이 문서는 Cokform을 소개하거나 브랜드 자산을 제작·배포할 때 지켜야 할 최소 기준을 정의합니다.

## 1. 브랜드 한 문장

Cokform은 채용·행사·교육·커뮤니티·고객 응대에 필요한 질문을 자유롭게 설계하고, 응답을 안전하게 운영하도록 돕는 **한국 실무형 폼 빌더**입니다.

| 구분 | 기준 |
|---|---|
| 국문 서비스명 | 콕폼 |
| 영문 서비스명 | Cokform |
| 기본 슬로건 | 원하는 대로, 콕 묻고 받아요 |
| 보조 설명 | 한국 실무 흐름에 맞춘 개인정보 보호형 폼 빌더 |
| 핵심 가치 | 자유도, 명확함, 실무성, 복구 가능성, 개인정보 보호 |
| 브랜드 성격 | 친근하지만 가볍지 않음, 신뢰감 있지만 딱딱하지 않음 |

Cokform은 기능의 개수보다 **질문을 만들고, 응답을 받고, 다음 운영으로 넘어가는 흐름**을 우선합니다. 제품·마케팅·문서의 모든 표현은 이 흐름에 기여해야 합니다.

## 2. 브랜드 메시지

### 2.1 핵심 메시지 계층

| 계층 | 문장 | 사용 위치 |
|---|---|---|
| 한 줄 | 원하는 대로, 콕 묻고 받아요 | 로고 옆, OG 이미지, 소개 문구 |
| 제품 설명 | 필요한 질문을 만들고, 응답을 받고, 다음 일을 시작하세요 | 홈 히어로, 랜딩 페이지 |
| 차별점 | 조건부 질문·개인정보 안내·응답 관리·복구를 한 흐름에 담았습니다 | 소개·영업 자료 |
| 개인정보 원칙 | 응답 원문은 작성자만 읽도록 설계했습니다 | 응답 안내, 보안 문서 |
| 책임 고지 | 폼 운영자는 수집 목적·항목·보유 기간을 직접 안내하고 관리해야 합니다 | 공개 폼, 정책 문서 |

### 2.2 말투

Cokform의 말투는 **짧고, 정확하고, 다음 행동이 보이는 존댓말**입니다. 기능을 자랑하기보다 사용자가 무엇을 할 수 있는지 먼저 말합니다. 어려운 보안 용어와 수동태를 줄이고, 개인정보와 암호화에 관한 문장은 설계 범위만 정확하게 표현합니다.

권장 문장은 “필요한 질문만 추가하세요”, “지원 분야에 따라 필요한 질문만 보여드려요”, “새로고침해도 작성 중인 답변을 이어갈 수 있어요”입니다. “100% 안전합니다”, “해킹이 불가능합니다”, “AI가 모든 응답을 완벽하게 처리합니다”처럼 검증할 수 없는 절대 표현은 사용하지 않습니다.

### 2.3 ‘콕’의 사용

‘콕’은 모든 문장에 반복해서 넣는 장식어가 아닙니다. 정확한 질문, 필요한 정보, 다음 행동을 강조할 때만 사용합니다. 예를 들어 “필요한 것만, 콕”, “콕 묻고 다음 일로”는 권장하지만, 모든 버튼을 “콕 저장”, “콕 삭제”로 바꾸는 방식은 피합니다.

## 3. 공식 브랜드 자산

공식 자산은 저장소의 `public/brand/`와 [Cokform 브랜드 리소스 센터](/resources)에서 관리합니다. 외부 배포물에는 임의로 다시 그린 로고를 사용하지 말고 공식 SVG를 우선 사용합니다.

| 자산 | 저장소 경로 | 권장 용도 |
|---|---|---|
| 기본 로고 | `public/brand/cokform-logo.svg` | 웹 헤더, 문서, 소개 자료, 밝은 배경 |
| 심볼 마크 | `public/brand/cokform-mark.svg` | 파비콘, 앱 아이콘, 프로필, 좁은 영역 |
| OG 이미지 | `public/og-image.png` 또는 `public/og-image.svg` | 링크 미리보기, 커뮤니티 공유 |
| 브랜드 상세 문서 | `docs/COKFORM_BRAND_GUIDE.md` | 브랜드 제작·검토 기준 |
| 제품 디자인 문서 | `docs/COKFORM_DESIGN_GUIDE.md` | UI 구현·QA 기준 |

### 3.1 로고 여백과 크기

로고 주변에는 다른 요소가 닿지 않도록 **로고 높이의 0.5배 이상**을 최소 여백으로 둡니다. 좁은 공간에서 기본 로고가 읽히지 않으면 심볼 마크로 전환하되, 워드마크 일부를 잘라 심볼처럼 사용하지 않습니다. 웹 헤더에서 기본 로고는 높이 28~36px을 기준으로 하고, 문서·커뮤니티 이미지에서는 비율을 유지한 채 충분한 여백을 확보합니다.

로고는 원본 비율을 유지해야 하며, 가로·세로 늘이기, 회전, 임의 색상 변경, 외곽선, 그림자, 그라데이션, 사진 위 직접 배치를 금지합니다. 대비가 낮은 배경에서는 로고를 배치하지 말고, 필요한 경우 Warm White 또는 단색 배경을 먼저 마련합니다.

### 3.2 파일 형식

| 형식 | 기준 | 사용처 |
|---|---|---|
| SVG | 해상도 제한 없는 원본 | 웹, 편집 프로그램, 인쇄 |
| PDF | 벡터 품질 유지 | 인쇄·제출용 문서 |
| PNG | 투명 배경 | 웹·디자인 작업 |
| JPG | 밝은 배경 포함 | 일반 업로드·문서 |

PNG와 JPG는 리소스 센터에서 목적에 맞는 해상도를 선택합니다. 기본 로고는 1024·2048·4096px, 심볼은 512·1024·2048px을 사용합니다. 인쇄물이나 편집 작업은 PNG를 억지로 확대하지 말고 SVG 또는 PDF를 우선합니다.

## 4. 색상

Cokform의 기본 화면은 따뜻한 아이보리와 짙은 잉크를 바탕으로 사용하고, 초록을 행동·상태의 신호로 사용합니다. 라임은 넓은 배경이나 본문 글자에 사용하지 않고 제한적인 강조에만 사용합니다.

| 토큰 | HEX | 역할 |
|---|---|---|
| Ink | `#17251F` | 본문·핵심 제목 |
| Deep Green | `#0F5B46` | 주요 버튼·브랜드 면·강한 상태 |
| Cokform Green | `#17866D` | 링크·선택·상호작용 |
| Leaf Green | `#73B99D` | 보조 선·그래픽 |
| Soft Mint | `#D8F5E8` | 선택됨·성공·보조 배경 |
| Warm White | `#FFFDF8` | 카드·문서·밝은 표면 |
| Canvas | `#F5F3EC` | 앱 전체 배경 |
| Lime | `#D8ED59` | 히어로 포인트·짧은 강조 |
| Coral | `#F28B70` | 보조 유형·주의 시각화 |
| Error | `#B94A48` | 오류·삭제·위험 안내 |

### 4.1 색상 사용 원칙

본문과 일반 제목은 Ink를 사용합니다. 기본 버튼의 흰 글자는 Deep Green 위에 배치합니다. 현재 Cokform Green과 Warm White의 대비는 약 4.43:1로 일반 텍스트 AA 기준에 아주 근소하게 못 미치므로, 작은 버튼 글자·본문·링크에는 Deep Green 또는 더 어두운 토큰을 사용합니다. 큰 텍스트나 아이콘의 강조 색상으로는 Cokform Green을 사용할 수 있습니다.

색상만으로 문항 유형·오류·필수 여부를 전달하지 않습니다. 텍스트 라벨, 아이콘, `aria-*` 상태, 명확한 제목을 함께 제공합니다. WCAG는 일반 텍스트에 최소 4.5:1, 큰 텍스트에 최소 3:1 대비를 요구합니다. [1]

## 5. 브랜드 사용 금지

Cokform의 로고와 심볼을 공식 제휴·보증·승인이 있는 것처럼 보이게 사용하지 않습니다. 다른 서비스의 로고와 같은 크기·간격으로 배치해야 하는 경우에도 Cokform의 공식 파트너십을 암시하는 문장을 추가하지 않습니다.

응답 암호화는 “작성자만 자신의 키로 읽도록 설계”라고 표현합니다. “Cokform은 어떤 경우에도 데이터를 볼 수 없다”처럼 구현·운영 조건을 넘어서는 단정은 정책과 실제 시스템을 확인한 뒤에만 사용합니다. 개인정보 수집의 적법성·목적·보유 기간에 대한 책임이 폼 운영자에게 있다는 점도 숨기지 않습니다.

## 6. 채널별 적용

| 채널 | 우선 자산 | 카피 원칙 |
|---|---|---|
| 웹·앱 | 기본 로고, 심볼, 토큰 | 한 화면의 대표 행동 하나를 명확히 |
| Discord·커뮤니티 | 심볼 또는 OG 이미지 | 작은 썸네일에서도 서비스명과 한국형 실무성이 보이게 |
| 문서·제안서 | 기본 로고·Deep Green | 장식보다 서비스 목적과 운영 사례를 먼저 |
| 채용·행사 폼 | 심볼·Warm White·Soft Mint | 응답자에게 수집 목적·필수 여부·마감 상태를 명확히 |
| 보안·정책 문서 | 기본 로고·Ink | 보장보다 설계 범위·책임·복구 방법을 정확히 |

## 7. 최종 배포 전 체크

배포 전에는 공식 SVG 사용 여부, 로고 비율과 최소 여백, 서비스명 표기, 슬로건 오탈자, 색상 토큰 사용, 링크 미리보기 이미지, 모바일 390px 화면, 키보드 포커스, 오류·필수 상태를 함께 확인합니다. 특히 색상으로만 상태를 구분하지 않았는지와 작은 텍스트의 대비가 4.5:1 이상인지 확인합니다.
