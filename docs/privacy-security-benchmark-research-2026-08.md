# Cokform 개인정보·보안 벤치마크 조사

조사일: 2026-08-18 KST

## 제공 사례: Catchsecu의 Google Forms 대비 개인정보 관리 글

원문: https://www.catchsecu.com/archives/18715

글은 설문 폼 운영자가 개인정보를 수집할 때 수집 목적, 수집 항목, 보유·이용기간을 명확히 고지하고, 수집 목적과 무관한 항목의 과수집을 피해야 한다는 문제를 제기한다. 또 안전한 인증, 접근 통제, 최신 보안 패치, 접속·다운로드 기록 점검, 보유기간 경과 정보의 파기, 마스킹, 정보주체 요청 처리의 필요성을 강조한다.

이 글은 벤더의 비교·홍보 콘텐츠이므로 법적·기술적 사실을 단독 근거로 삼지 않는다. 그러나 Cokform에 대한 다음의 유효한 점검 축을 제공한다.

| 점검 축 | Cokform 적용 후보 |
|---|---|
| 최소수집 | 질문별 개인정보 가능성 경고, 목적과 관계없는 항목 경고 |
| 동의 고지 | 목적·항목·보유기간·거부권을 빠짐없이 작성하도록 가이드·검증 |
| 보유·파기 | 보유기간 설정, 만료 알림·응답 파기, 파기 이력 |
| 접근·내보내기 | 작성자 전용 복호화·내보내기 기록, 다운로드 원문 보호 |
| 정보주체 권리 | 응답 철회·삭제 요청을 위한 안전한 토큰 기반 경로 |
| 운영 안전성 | 키 백업·복구 경고, 보안 이벤트·접근 이력, 최신 의존성 관리 |

후속 단계에서 개인정보보호위원회·국가법령정보센터·OWASP 등 공식 또는 독립 출처로 법적 의무와 구현 방향을 교차 검증한다.

## 공식·독립 출처 교차 검증

개인정보보호위원회(PIPC)의 개인정보처리방침은 최소수집, 처리 목적 외 이용 시 별도 조치, 수집 시점에 고지하거나 법령에 따른 보유기간 내 처리, 목적 달성·보유기간 만료 시 파기라는 원칙을 명시한다. 또한 열람·정정·삭제·처리정지 요청의 경로와 행정·기술·물리적 안전조치를 공개한다. 전자 파일 파기는 복원이 불가능한 기술적 방법을 사용해야 한다고 설명한다.

OWASP Logging Cheat Sheet는 보안 로그가 인증·인가 실패, 데이터 생성·변경·삭제, 데이터 내보내기, 암호화 키 관련 고위험 활동, 법적 동의 등 보안·운영 사건의 감사 추적에 필요하다고 권고한다. 동시에 로그에는 액세스 토큰, 비밀번호, 암호화 키, 민감·식별 개인정보를 직접 남기지 말고 제거·마스킹·해시·암호화해야 한다고 명시한다.

| 공식 원칙 | Cokform 설계 판단 |
|---|---|
| 최소수집·목적 명확화 | 폼 작성 화면에서 개인정보 가능 질문을 감지·경고하고, 수집 목적·보유기간 없이 개인정보 동의 문항을 활성화하지 않도록 개선 후보 |
| 목적 달성·보유기간 만료 시 파기 | 응답 데이터의 암호문 자동 만료와 파기 예약은 높은 우선순위. 파기 전 작성자 알림과 파기 이력도 필요 |
| 정보주체 권리 | 본인 응답을 식별·삭제 요청할 수 있는 비밀 토큰 기반 경로 필요. 이메일·전화 기반 검색은 추가 개인정보를 만들므로 기본값으로 부적합 |
| 안전조치 | 작성자 전용 RLS·브라우저 E2EE를 유지하고, 키 백업·복구 경고·내보내기 안전장치를 강화 |
| 감사 기록 | 응답 원문·키·토큰 없이 폼/응답 삭제, 내보내기, 권한 변경, 보존 정책 변경 등 메타데이터만 기록 |

- PIPC 개인정보처리방침: https://www.pipc.go.kr/eng/user/cmm/privacyGuideline.do
- OWASP Logging Cheat Sheet: https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html

## 2025 개정 안전성 확보조치 기준의 Cokform 관련 요구

국가법령정보센터의 「개인정보의 안전성 확보조치 기준」은 개인정보처리시스템의 접근권한을 업무상 최소 범위로 차등 부여하고, 권한 부여·변경·말소 기록을 최소 3년 보관하며, 계정 공유를 막고 안전한 인증수단을 적용하도록 규정한다. 외부에서 시스템에 접속하는 정당한 권한자에게는 안전한 인증수단을 적용해야 하며, 접근기록은 원칙적으로 1년 이상(대량·민감·고유식별 정보 처리 시 2년 이상) 보관하고 다운로드 상황을 확인·점검해야 한다.

같은 기준은 화면표시·파일생성 등 개인정보 출력 시 용도를 특정하고 출력 항목을 최소화할 것, 파기 시 복원이 불가능한 방법을 사용할 것, 그리고 내부관리계획에 출력·복사 안전조치, 파기, 유출사고 대응, 위험분석, 수탁자 관리 등을 포함할 것을 명시한다. 2025년 개정 해설은 플랫폼을 이용해 개인정보를 처리하는 사업자도 안전한 인증·접속기록·접근권한·인증 실패 제한의 적용 범위가 확대됐다고 설명한다.

| 기준상 통제 | Cokform 현재 상태 | 적용 우선순위 |
|---|---|---|
| 최소권한·계정 분리 | Google OAuth·RLS로 작성자 분리. 공동작업자 권한 모델은 아직 얕음 | P1 |
| 인증 실패·세션 보호 | OAuth 제공자에 의존. 별도 비밀번호가 없음 | P2, OAuth 설정·MFA 정책 문서화 |
| 접속·다운로드 점검 | 조회 수·응답 수는 있으나 내보내기·파기 감사 이력은 없음 | P0 |
| 출력 항목 최소화 | CSV·Excel은 전체 원문, PNG·PPTX는 요약. 출력 목적 표시는 없음 | P0 |
| 보유기간·복구불가 파기 | 수동 응답 삭제만 존재 | P0 |
| 유출 대응·내부관리계획 | 공개 문서 수준의 안내만 존재 | P1 |

## 개인정보 수집 동의 UX의 구체 요구

국가법령정보센터의 개인정보 보호법 제15조는 동의를 받는 수집·이용에 대해 수집·이용 목적, 항목, 보유·이용 기간, 동의 거부권과 불이익을 알려야 한다고 규정한다. 제16조는 목적에 필요한 최소한의 개인정보만 수집하고, 최소한을 넘는 정보에 동의하지 않을 수 있음을 구체적으로 알리도록 한다. 제21조는 필요 없어진 개인정보를 지체 없이 복구 불가능하게 파기하도록 하고, 제22조는 동의 사항을 구분해 명확히 인지할 수 있도록 동의를 받도록 한다. 제23조는 민감정보를 다른 개인정보와 별도로 동의받는 경우 외에는 원칙적으로 처리하지 못하도록 제한한다.

따라서 Cokform에서 `서비스를 이용하면 약관에 동의한 것으로 봄`이라는 서비스 약관 고지와, 개별 설문에서 개인정보를 수집하기 위한 명시적 동의는 기능·문구·저장 기록에서 반드시 분리되어야 한다. 이 원칙은 기존 약관에도 반영되어 있으나, 폼 작성 UI의 예방 장치가 아직 부족하다.

| 유형 | 작성 UI 기본값 | 필요한 동의·경고 |
|---|---|---|
| 연락처·이름·주소·이메일 | 개인정보 가능성 경고 | 목적·항목·보유기간·거부권을 명시하는 별도 수집·이용 동의 |
| 건강·정치·종교·노조 등 | 민감정보 경고 | 다른 개인정보 동의와 분리된 별도 동의와 수집 필요성 재확인 |
| 주민번호·여권·운전면허 등 | 기본 차단 | 법령 근거·별도 동의·강화 안전조치가 없으면 질문 추가 금지 |
| 선택 질문 | 기본 선택형 | 미동의/미응답을 이유로 핵심 서비스 제공을 거절하면 안 된다는 안내 |
| 제3자 제공·외부 자동 전송 | 기본 비활성 | 수령자·목적·항목·보유기간·거부권을 별도 명시하고 동의를 분리 |

## Cokform 위험 모델과 이번 적용 범위

Cokform은 작성자 브라우저에서 응답 원문을 암호화하고 Supabase에는 암호문을 저장한다. 따라서 플랫폼 운영자가 평문 응답을 조회하지 않는 구조는 강점이다. 그러나 암호화만으로는 폼 운영자의 과수집, 동의 고지 누락, 보유기간 만료 후 방치, 외부 내보내기, 고위험 식별정보 수집을 해결하지 못한다.

| 위험 | 현재 공백 | 이번 적용 | 후속 과제 |
|---|---|---|---|
| 과수집·민감정보 | 질문 제목 기반 예방 없음 | 개인정보·민감정보·고유식별정보 키워드 점검과 고위험 공유 차단 확인 | AI/규칙 기반 항목 분류 고도화, 업종별 템플릿 |
| 동의 누락 | 안내가 선택 사항이고 거부권 문구 부족 | 필수 고지 완결성 점검, 거부권·불이익 문구, 제3자·위탁 상세 고지 | 별도 동의 유형과 동의 증빙의 세분화 |
| 보유기간 만료 | 값만 있고 실제 파기 예약 없음 | 제출 시 만료시각 고정, DB 일일 파기, 파기 메타 이력 | 파기 전 알림·보존 연장 재동의 흐름 |
| 내보내기·삭제 추적 | 감사 이력 없음 | 원문 없는 내보내기·일괄 삭제·자동 파기 메타 이력 | 작성자용 감사 이력 화면·이상 탐지 |
| 정보주체 권리 | 응답 철회·삭제 요청 경로 없음 | 응답자에게 보유기간·운영자 문의 경로 고지 | 본인 확인형 철회 토큰/삭제 요청 흐름 |

이번 구현은 개인정보보호법 준수를 보장하거나 법률 자문을 대체하지 않는다. 고위험 질문의 키워드 감지는 누락·오탐이 가능한 예방 보조 장치이며, 수집의 적법성·별도 동의·법정 보존 의무 판단은 실제 폼 운영자의 책임 아래 이뤄져야 한다.
