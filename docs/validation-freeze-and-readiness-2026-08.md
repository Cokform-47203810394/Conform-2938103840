# 콕폼 검증 동결 및 컨시어지 테스트 준비 결정

**결정일:** 2026-08-20  
**상태:** 제품 확장 기능 동결. 검증·복구·측정·회귀 방어만 진행.

> **결정:** 새 양식 유형, 새 템플릿, 새 통합, 새 PRO 기능은 컨시어지 테스트 결과가 나오기 전까지 추가하지 않는다. 예외는 테스트, 오류 복구, 개인정보 최소화, 측정, 접근성, 데이터 백업·복구처럼 현재 사용자를 안전하게 만드는 작업뿐이다.

## 외부 피드백 사실 판정

| 피드백 | 판정 | 현재 근거 | 결정 |
|---|---|---|---|
| 기능을 너무 많이 만들고 실사용 검증이 없다 | **정확** | 실사용 파일럿 데이터가 없는 상태에서 편집·템플릿·내보내기·브랜딩 범위가 넓어졌다 | 기능 확장 동결 |
| sunk cost 신호가 있다 | **정확** | 경쟁사 기능을 따라간 기능이 있고, 활성화·재사용 데이터로 유지 여부를 판단하지 못한다 | 기능별 유지/삭제 판단표 작성 |
| 완료 정의가 없다 | **정확** | 배포 여부와 사용자 가치 검증 여부가 한 상태로 섞여 있다 | 아래 DoD 적용 |
| 기능별 ‘왜’가 기록되지 않는다 | **정확** | 코드·문서는 많지만 사용자 문제와 증거가 일관된 형식으로 연결되지 않는다 | 기능 결정 기록 강제 |
| 자동 테스트가 없다 | **정확** | 현재 패키지에 테스트 러너·E2E 도구가 없고 테스트 파일도 없다 | 첫 코드 작업은 회귀 테스트 기반 구축 |
| Error Boundary가 없다 | **부정확** | 전역 `AppErrorBoundary`와 공개 응답용 `RespondPageErrorBoundary`가 이미 배포됨 | 추가 기능이 아니라 현재 경계의 회귀 테스트 필요 |
| 1회 응답 제한은 시크릿 모드로 우회된다 | **부분적으로 정확** | 서버는 원자적 정원·토큰 중복·IP 속도 제한을 적용하지만, 브라우저 토큰은 새 프로필/시크릿 창에서 새로 생긴다 | 채용·선별에는 ‘브라우저 1회’ 제한을 쓰지 않는다 |
| 문항 유형은 색만으로 구분된다 | **부분적으로 부정확** | 문항에는 Q 번호·유형 텍스트가 함께 보인다. 다만 색 외 아이콘 신호는 부족하다 | 접근성 P1: 유형 아이콘·텍스트 레이블 강화 |
| 로고가 가안일 수 있다 | **정확** | 현재 브랜드 자산은 사용 가능하나, 전문 브랜드 제작물로 고정됐다고 볼 근거가 없다 | 외부 디자이너 브리프에 ‘시각 체계는 조정 가능’ 명시 |
| 측정 인프라가 없다 | **정확** | Plausible·GA·PostHog 등 분석 도구와 이벤트 수집이 현재 없다 | 개인정보 없는 활성화 이벤트만 우선 수집 |
| ‘콕’ 네이밍 스토리가 카피에 없다 | **정확** | 서비스명은 보이지만 ‘필요한 것을 정확히 집는다’는 브랜드 의미가 반복되지 않는다 | 사례·온보딩에 1문장으로만 적용 |
| 개인정보처리방침 초안이 없다 | **부정확** | `/privacy`와 관련 공개 정책 페이지가 배포되어 있다 | 법률 검토·책임자/사업자 정보 보완은 여전히 미완료 |
| 컨시어지 테스트의 개인정보 흐름이 검토되지 않았다 | **정확, P0** | 운영자가 신청자 원문을 직접 받거나 대신 다루는 경우 역할·동의·보관·파기 범위가 별도로 필요하다 | 아래 안전 프로토콜 외 방식으로 테스트 금지 |

## 기능 유지·삭제 판단표

모든 기존 기능은 다음 표를 채우기 전까지 ‘유지 확정’이 아니다.

| 필드 | 작성 기준 |
|---|---|
| 기능명 | 사용자가 인지하는 이름 |
| 해결하려는 문제 | 사용자 관찰 문장으로 작성. 예: “행사 운영자가 취소자에게 다시 연락해야 한다.” |
| 대상 사용자 | 행사 운영자, 교육 운영자, 커뮤니티 운영자 등 1개 |
| 가설 | 이 기능이 시간을 줄이거나 오류를 줄인다는 문장 |
| 최소 성공 신호 | 실제 폼 생성, 공개 링크 공유, 7일 재사용, 인터뷰 발화 중 하나 |
| 유지 기준 | 테스트 참여자 3명 이상이 실제 업무에 다시 사용 |
| 제거 기준 | 사용 장면이 없거나, 기존 흐름을 복잡하게만 만들 때 |
| 데이터 민감도 | 없음 / 일반 / 개인정보 / 민감 가능성 |

## Definition of Done

‘완료’는 코드가 끝났다는 뜻이 아니다. 아래 네 단계를 분리해 기록한다.

| 단계 | 완료 조건 |
|---|---|
| 구현 완료 | 코드 리뷰·빌드 통과·배포 가능 상태 |
| 배포 완료 | 운영 배포 성공, 핵심 화면 스모크 확인 |
| 안전 완료 | 오류 경계, 권한, 개인정보·복구·회귀 영향 확인 |
| 검증 완료 | 대상 사용자 3명 이상이 실제 업무에서 사용하고, 재사용 또는 명확한 거절 이유 확보 |

기능은 ‘검증 완료’가 되기 전에는 성공으로 표시하지 않는다. 배포됐지만 쓰이지 않은 기능은 **보류된 가설**이다.

## 컨시어지 테스트 안전 프로토콜

> 법률 안내: 아래는 제품 운영을 위한 실무적 위험 관리안이며, 개인정보 처리 역할과 계약·동의 요건은 실제 테스트 방식과 대상에 따라 달라질 수 있다. 공개 테스트나 신청자 원문을 직접 다루기 전에는 개인정보보호 전문 변호사 또는 전문가 검토가 필요하다.

1. **원문을 대신 받지 않는다.** 콕폼 운영자가 신청자의 원문·첨부·주민번호·계좌·건강·이력서를 채팅·메일로 받지 않는다.
2. **빈 양식 또는 가상 데이터만으로 세팅한다.** 운영자의 실제 질문 구조는 받을 수 있으나, 이름·연락처·지원 내용은 더미 데이터로 치환한다.
3. **폼 소유자를 명확히 한다.** 테스트 양식의 소유자는 해당 행사·교육·커뮤니티 운영자이며, 콕폼은 응답 원문을 열람하지 않는다.
4. **지원 요청의 범위를 고지한다.** ‘양식 구조·설정 지원만 제공하며 응답 내용은 보지 않는다’는 문장을 파일럿 안내에 넣는다.
5. **테스트 종료 기준을 정한다.** 파일럿 종료일, 응답 보관 기간, 운영자 스스로 삭제/내보내기 책임을 사전에 안내한다.
6. **민감한 사용처를 제외한다.** 채용, 의료, 금융, 미성년자 대상, 민감정보 수집 폼은 첫 컨시어지 테스트 대상에서 제외한다.

## 측정 이벤트 최소안

응답 원문과 암호화 키를 수집하지 않고 다음 이벤트만 집계한다.

- 유입 출처(UTM), 템플릿 열람, 빈 양식 생성, 첫 질문 추가, 공개 링크 생성, 7일 재방문, 내보내기 실행, 오류 경계 도달.
- 이벤트에는 이메일, 답변, 개인키, 응답 원문을 넣지 않는다.

## 응답 1회 제한 정책

현재 `브라우저 1회 제한`은 일반 설문·가벼운 신청에서만 보조 UX로 쓴다. 새 브라우저 프로필이나 시크릿 모드에서 바뀔 수 있으므로, 채용·선별·경품·투표처럼 공정성 판단이 필요한 용도로 사용하지 않는다.

그런 폼에는 별도 설계가 필요하다. 예를 들어 Google 로그인 기반 계정 1회 제한, 초대 토큰, 운영자 승인, 또는 외부 본인 확인 중 하나를 명시적으로 선택해야 한다. ‘한 사람 1회’를 보장할 수 없는 상태에서는 그렇게 보이는 문구를 쓰지 않는다.
