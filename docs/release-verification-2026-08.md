# Cokform 릴리스 검증 기록

## 2026-08-18 KST — 안정성·연동·내보내기 개선

로컬 최신 빌드의 홈 화면을 브라우저로 확인했다. READY-MADE FLOWS 영역은 `PRO · 무료 공개 중`과 파일럿 기간 무료 안내를 표시하며, 각 프리미엄 템플릿 배지는 `무료`로 표시된다. 푸터의 문의처는 `seoharo0111@gmail.com` mailto 링크로 반영됐다.

Production build는 암호화 버전 이력, 삭제 확인 모달, CSV·Excel·JSON·요약 PNG·PPTX 내보내기, 사용자 선택형 Google Sheets·Drive 업로드 코드까지 포함해 성공했다. PptxGenJS를 이용한 실제 PPTX 생성 smoke test도 정상 파일 생성으로 확인했다.

Google Sheets·Drive 직접 업로드는 사용자가 버튼을 누를 때만 `drive.file` 최소 권한을 요청하도록 설계했다. 자동 동기화는 구현·활성화하지 않았으며, 응답 원문을 자동으로 외부 서비스에 전송하지 않는다.

로컬 `/terms` 페이지에서는 `2026년 8월 18일` 시행일, 서비스 이용 시 약관·개인정보처리방침의 적용을 확인하는 문구, 그리고 `seoharo0111@gmail.com` 문의처가 정상 렌더링되는 것을 확인했다.

브라우저 번들에서 샘플 응답으로 요약 PNG Blob(80,661 bytes) 생성과 동적 PPTX 내보내기 다운로드 시작을 확인했다. 요약 이미지·프레젠테이션은 자유 입력 원문을 포함하지 않고 집계 결과만 사용한다.


Supabase 보안 진단에서 외부 RPC로 호출될 수 있던 `SECURITY DEFINER` 함수 3개의 `anon`·`authenticated` 실행 권한을 회수했다. 재진단 결과 해당 경고는 모두 사라졌으며, 남은 경고는 현재 Google OAuth만 사용하는 파일럿에서 비활성 상태인 비밀번호 로그인용 유출 비밀번호 보호 설정이다.


Vite 8 기반 코드 분할 후 로컬 홈과 `/terms`를 다시 브라우저에서 확인했다. 홈의 무료 PRO 안내·문의 푸터가 유지됐고, 지연 로드된 약관 화면도 시행일·이용 동의·문의처를 정상 표시했다.


참여 폼 이력 기능은 최신 로컬 홈에서 빈 상태와 샘플 최소 메타데이터 카드로 검증했다. 카드에는 폼 제목·문항 수·참여 시각·공개 폼 재열기만 표시되며, 응답 원문·이메일·암호화 키는 렌더링되지 않았다.

운영 Supabase 보안 진단을 참여 이력·자동 파기 배포 뒤 재실행했다. 새 참여 이력 테이블과 자동 파기 함수 관련 RLS·공개 실행 권한 경고는 없었다. 남은 경고는 비밀번호 로그인용 유출 비밀번호 보호가 비활성이라는 Auth 권고이며, 현재 Cokform은 Google OAuth만 사용한다. 향후 비밀번호 로그인을 추가할 경우 해당 보호 기능을 먼저 활성화해야 한다.

개인키 금고 Web Crypto smoke test를 브라우저에서 수행했다. 12자 이상 복구 비밀번호로 키 금고를 생성한 뒤, form ID와 `response` 용도에 결합된 v2 AES-GCM 암호문을 생성·복호화했다. 금고 잠금 뒤에는 복호화가 `null`로 차단됐고, 같은 복구 비밀번호로 재잠금 해제하면 정상 복호화됐다. 내보낸 `.cokform-key.json` 키 백업 문자열에는 ECDH private JWK의 `d` 필드가 포함되지 않았다.

## 2026-08-18 — 전체 암호화 복구 번들 검증

로컬 Vite 환경에서 Web Crypto API를 사용해 격리된 테스트 폼으로 전체 복구 번들 흐름을 검증했다. PBKDF2-HMAC-SHA-256 기반 키 금고를 생성하고 ECDH P-256/AES-256-GCM 응답 봉투를 복호화한 뒤 금고를 잠갔다. 잠금 상태에서는 복호화 결과가 `null`이었고, 올바른 복구 비밀번호로 번들을 연 뒤 금고를 재가져오자 원 응답이 정상 복호화됐다.

| 확인 항목 | 결과 |
|---|---|
| 잠금 전 응답 복호화 | 통과 |
| 잠금 중 응답 평문 노출 | 차단 (`null`) |
| 암호화 키 백업에 private JWK `d` 포함 | 없음 |
| 전체 복구 번들 형식 | `cokform-encrypted-form-recovery` |
| 번들에 암호문 응답 1건 복원 | 통과 |

이 검증은 키 금고·암호 봉투·번들 암호화의 브라우저 단위 동작을 다룬다. Supabase 대상 실제 복구는 별도 신규 프로젝트에서 검증해야 한다.

추가 무결성 검증에서는 세 가지 모두 차단됐다. 다른 복구 비밀번호로 번들을 열려는 시도, 암호문 끝부분을 바꾼 번들을 여는 시도, 동일 응답 암호문을 `form-version` 용도로 복호화하려는 시도가 각각 복호화 예외로 종료됐다. 즉, 복구 비밀번호와 AES-GCM 인증 태그, 그리고 form ID·용도 AAD 바인딩이 모두 동작한다.

Cloudflare Pages 배포 워크플로는 커밋 `ce11f85`에서 성공했다. 운영 URL `https://cokform.pages.dev`의 홈 화면도 2026-08-18 KST에 정상 렌더링됨을 확인했다. 이전 GitHub Pages 워크플로는 Cloudflare 배포와 중복되고 이 서비스의 기준 URL이 아니므로 제거했으며, 이후 푸시에는 Cloudflare Pages 워크플로만 실행된다.

첫 화면 폼 카드용 커버 이미지 기능은 로컬 프로덕션 빌드에서 다시 컴파일했다. 커버 이미지 URL 정화 규칙은 HTTPS와 사이트 상대 경로만 허용하고, `http:` 및 `javascript:` URL을 거부함을 브라우저에서 확인했다. 업로드 형식은 PNG·JPG·GIF·WebP로 제한하며, 카드용 업로드는 1MB 이하로 제한한다.

응답 시작·마감 시각과 즉시 재오픈 기능은 로컬 프로덕션 빌드를 통과했다. 운영 Cokform Supabase에는 공개 삽입 RLS 정책을 갱신해 `acceptingResponses`, `responseStartAt`, `responseEndAt`을 데이터베이스의 `now()`와 비교하도록 적용했고, 적용된 정책 정의도 조회로 확인했다. 브라우저 Web Crypto 개발 환경에서는 기간 제한 없음(`open`), 시작 전(`not_started`), 기간 마감(`ended`), 수동 마감(`manually_closed`) 상태와 마감 안내 문구를 모두 정상 판정했다.

이메일 주소 기록 기능은 `collectEmail` 설정이 켜진 경우에만 응답자 화면에 명확한 기록 고지와 필수 이메일 입력을 표시하도록 확장했다. 이메일 값은 기존 응답 암호화 봉투 안에 포함되며, 제작자 응답 화면에는 별도 이메일 목록 카드로 표시한다. 브라우저 개발 번들에서 `responseRows()`를 검증해 CSV·Excel·JSON에 사람 친화적인 `이메일 주소` 열과 값이 정상 생성됨을 확인했다.
응답자 이메일 기록 UI의 최신 개발 번들도 확인했다. 응답 화면 고지(`이 양식은 이메일 주소를 기록합니다`), 제작자 이메일 카드(`기록된 이메일 주소`), 이메일 `autocomplete` 및 필수 입력 속성이 모두 포함된다.
운영 URL의 390×844 모바일 뷰포트도 확인했다. 확대된 한국어 로고 슬로건, 알림·설정·로그인 동작 영역, 두 번째 줄의 검색 입력이 겹치지 않고 표시되며, 핵심 시작 카드와 템플릿 가로 스크롤도 정상이다.
