# Cokform 독립 운영 매뉴얼 시스템

이 문서는 콕폼을 **대표 혼자, 새 협업자와 함께, 또는 담당자가 바뀐 뒤에도** 운영할 수 있게 만든 진입점이다. 모든 문서를 처음부터 읽을 필요는 없다. 먼저 현재 역할과 상황을 고르고, 아래 순서대로 연다.

> 새 세션·새 AI·새 컴퓨터에서 시작하면 먼저 [AI·운영자 시작 안내서](./AI_AND_OPERATOR_START_HERE.md)와 [최신 마스터 컨텍스트](./MASTER_CONTEXT_COKFORM_CURRENT.md)를 읽는다. 이 문서는 그 다음에 2,000개 세부 매뉴얼을 찾는 용도다.

| 먼저 할 일 | 열 파일 | 언제 쓰나 |
|---|---|---|
| 현재 상태와 이식 경계 확인 | [최신 마스터 컨텍스트](./MASTER_CONTEXT_COKFORM_CURRENT.md) | 새 세션·새 AI·새 컴퓨터에서 시작할 때 |
| 역할·상황 진입 안내 | [AI·운영자 시작 안내서](./AI_AND_OPERATOR_START_HERE.md) | 무엇부터 읽고 실행할지 모를 때 |
| 절대 원칙 확인 | [핵심 플레이북](./operations-manuals/00-core-playbooks.md) | 배포·키·응답·개인정보·장애를 다룰 때 |
| 역할별 판단 확인 | [역할별 실전 플레이북](./operations-manuals-source/01-role-playbooks.md) | 창업가, 기획, 개발, 보안, 지원 등 역할을 맡을 때 |

| 세부 상황 찾기 | [2,000개 인덱스](./operations-manuals/INDEX.csv) | 역할·업무·상황에 딱 맞는 체크리스트가 필요할 때 |
| 도메인별 찾기 | [도메인 목록](./operations-manuals/DOMAIN-README.md) | 보안, 지원, 마케팅, 비용 등 분야부터 찾을 때 |

## 이 매뉴얼의 구조

2,000개 세부 매뉴얼은 **20개 도메인 × 10개 업무 흐름 × 10개 상황**으로 만들었다. 각 세부 항목은 같은 형식이다. 목적, 역할, 시작 조건, 6단계 절차, 판단 기준, 금지 사항, 기록, 완료 조건, 다음 연결을 제공한다.

| 요소 | 의미 | 예시 |
|---|---|---|
| 도메인 | 책임 분야 | `SEC` 보안·암호화·키 |
| 업무 흐름 | 반복하는 일 | `03` 키 복구 테스트 |
| 상황 | 일을 해야 하는 맥락 | `08` 개인정보 포함 가능성 |
| ID | 매뉴얼 고유 번호 | `COK-SEC-03-08` |

## 사용 순서

> **원칙 → 체크리스트 → 세부 매뉴얼 → 기록** 순서로 사용한다. 세부 매뉴얼만 읽고 위험한 일을 시작하지 않는다.

예를 들어 공개 응답이 제출되지 않는다면, 먼저 핵심 플레이북의 ‘장애 대응 원칙’을 읽는다. 다음으로 핵심 체크리스트의 ‘공개 응답·E2EE 제출 장애’를 실행한다. 이후 `OPS`, `BEN`, `SEC` 도메인에서 현재 상황에 맞는 `COK-...` 항목을 인덱스로 찾아 연다. 마지막으로 버그 보고 템플릿에 원인·확인 범위·다음 행동을 기록한다.

## 독립 운영의 7개 절대 규칙

1. 개인키, 복구 비밀번호, 키 백업, 응답 원문을 어떤 지원 채널·이슈·분석 도구에도 넣지 않는다.
2. 사용 증거 없이 새 기능을 추가하지 않는다. 현재는 기능 확장 동결 상태다.
3. 빌드 통과와 배포 성공을 사용자 검증 완료로 혼동하지 않는다.
4. 삭제, 권한 변경, 배포 전에는 되돌릴 방법과 영향 범위를 먼저 적는다.
5. 일반 브라우저 1회 제한을 신원·공정성 보장으로 말하지 않는다.
6. 컨시어지 테스트에서는 실제 신청자 원문을 받지 않고 더미 데이터만 쓴다.
7. 분석에는 유입·생성·공유·재방문처럼 원문 없는 행동만 넣는다.

## 재생성 방법

세부 2,000개 체크리스트는 재생성 가능하다. 저장소 루트에서 아래 명령을 실행한다.

```bash
python3 scripts/generate_manual_system.py
```

생성 전용 파일은 `docs/operations-manuals/`이고, 사람이 고쳐야 하는 원칙·체크리스트·템플릿은 `docs/operations-manuals-source/`에 있다. 실제 제품 구조가 바뀌면 원본 문서를 먼저 고친 뒤 생성기를 수정하고 다시 실행한다.

## 현재 운영 우선순위

현재 콕폼은 기능을 더 만드는 단계가 아니다. 테스트, 키 복구 확인, 개인정보 없는 측정, 컨시어지 3회, 실제 재사용 또는 거절 이유 확보가 먼저다. 상세 기준은 [검증 동결 및 준비 결정](./validation-freeze-and-readiness-2026-08.md)을 따른다.
