## 4. E2EE·개인키 복구 경계

### 설계

- 폼마다 ECDH P-256 키쌍을 사용한다.
- 서버에는 공개키와 암호화된 응답 봉투만 저장한다.
- 응답은 임시 ECDH + AES-256-GCM으로 암호화하며 AAD는 `cokform:response-envelope:v2:{formId}:{purpose}`다.
- 개인키는 PBKDF2-HMAC-SHA256 600,000회와 AES-256-GCM으로 브라우저 localStorage 금고에 암호화한다.
- 개인키는 서버로 전송하지 않는다.

### 절대 규칙

1. 개인키, 복구 비밀번호, 키 백업, 전체 복구 번들, 실제 응답 원문을 지원 채널·로그·테스트·분석 도구에 넣지 않는다.
2. 기존 공개키가 있으나 현재 브라우저에 맞는 개인키가 없으면 **새 금고를 생성하지 않는다.** 기존 응답을 고아로 만들 수 있다.
3. 비밀번호를 잊어도 암호문 데이터는 보관 기간까지 남는다. 복구는 사용자가 보관한 키 백업, 전체 복구 번들, 기존 로그인 기기에서만 가능하다.
4. 서비스가 ‘비밀번호 재설정’으로 응답을 열어주면 E2EE 경계가 깨진다. 그런 기능을 만들지 않는다.

### 복구 UX 다음 P0

- 최초 키 금고 생성 후 복구 파일 저장을 명확한 단계로 만든다.
- 사용자 기기에서 복구 파일로 새 환경 복구를 한 번 검증하게 한다.
- 다른 로그인 기기가 있을 때 새 복구 파일을 재발급할 수 있게 한다.
- 전부 잃은 경우 서비스도 열 수 없다는 사실을 숨기지 않는다.

## 5. 응답 제출·공정성 한계

- Turnstile은 실제 사용자 오탐으로 제거했다.
- 제출 방어는 숨은 honeypot, 최소 1.5초 체류, 서버 HMAC IP 속도 제한, 원자적 정원 제한, E2EE 봉투 검증으로 구성된다.
- `maxResponses`는 서버 RPC에서 원자적으로 확인한다.
- `limitOneResponse`의 응답자 토큰은 브라우저 localStorage 기반이다. 서버가 중복 토큰을 막지만 새 브라우저 프로필·시크릿 창에서는 새 토큰이 생긴다.

> 따라서 브라우저 1회 제한은 일반 설문·가벼운 신청의 보조 UX다. 채용, 투표, 경품, 선별처럼 한 사람 1회 또는 공정성이 필요한 용도에 사용하거나 보장 문구를 쓰지 않는다. 그 경우 로그인 계정, 초대 토큰, 승인 절차 또는 외부 본인 확인을 명시적으로 설계해야 한다.

## 6. UI·브랜드 최근 변경

### 홈

- 핵심 문장: `접수부터 마감까지, 내 방식대로.`
- 실무 맥락: 행사·교육·커뮤니티 신청, 질문·동의·마감 조건.
- 템플릿은 가짜 질문 미리보기 대신 제목·용도·문항 수·개인정보 안내를 보여 준다.
- 템플릿 행은 자동 순환, 끌기, 이전/다음, 위치 표기를 갖춘 캐러셀이다.
- 빈 양식은 실제 빈 캔버스다. 질문/섹션을 강제하지 않는다.
- 템플릿·통계·폼·참여 이력은 동일한 둥근 흰 카드 반복 대신 작업대·정보 행·목록·실제 콘텐츠 미리보기로 분리했다.

### 편집기

- 선택 문항만 상세 편집하고, 나머지는 제목·유형·한 줄 요약으로 접는다.
- 새 문항·복제 문항은 바로 선택된다.
- 상단은 공유·보기·더보기로 묶었다.
- 빈 양식에 질문 추가, 목적 작성, 사본으로 시작이라는 실제 시작 행동을 제공한다.

### 응답자 화면

- 개인정보 고지·이메일 안내가 폼 본문을 가리지 않도록 축소·확장형으로 정리했다.
- `PreviewForm.jsx`의 누락 import로 생긴 과거 공백 화면은 수정됐다.
- 공개 응답 페이지와 전체 앱에 오류 경계가 있다.

### 응답 운영 화면

- 질문별 그래프/개별 응답 탭 구조를 제거했다.
- 기본 화면은 ‘제출 기록’이다. 한 응답 안에서 **누가, 언제, 무엇을 제출했고, 지금 어떻게 처리하는지**를 본다.
- 이름/이메일/답변 검색, 처리 상태 필터, 상태 변경, 단일 삭제, 원문 내보내기가 유지된다.

### 타이포그래피·카드

- 숫자·카운트에서 `font-mono`를 제거하고 Pretendard 비례 숫자로 통일했다.
- 본문과 보조 정보는 normal, 조작 요소는 medium, 핵심 제목만 bold를 사용한다.
- 그림자와 동일 반경·테두리의 카드 반복을 줄였다.

### 공유 이미지

- `public/og-image.png`는 한국 행사·신청서·일정표 맥락의 새 OG 이미지다.
- OG 제목: `콕폼 · 한국 실무에 맞춘 폼`
- Discord 등 플랫폼의 기존 링크 미리보기는 해당 플랫폼 캐시 때문에 새 메시지에서 갱신될 수 있다.

## 9. 테스트·측정 공백

- 현재 테스트 파일과 테스트 러너는 없다. 이것은 가장 큰 개발 공백이다.
- 첫 테스트 범위: 로그인 여부에 따른 화면, 폼 생성, 질문 추가/저장, 공개 링크 열기, 제출 오류, 키 없는 응답 원문 차단.
- 현재 Plausible/GA/PostHog 등 분석 도구는 연결되지 않았다.
- 측정 이벤트에 이메일, 응답 원문, 개인키, 복구 수단을 넣지 않는다.
- 측정 가능한 최소 이벤트: 유입 UTM, 템플릿 열람, 빈 양식 생성, 첫 질문 추가, 공유 링크 생성, 7일 재방문, 내보내기, 오류 경계 도달.

## 11. 대화·결정 요약

### 사용자 요구의 지속 원칙

- 한국어 중심, 한국 실무용, 모바일 우선.
- 인프라 비용 월 1만 원 이하.
- 답변 원문은 작성자만 읽는 E2EE 지향.
- 문서가 외부 사이트로 빠지지 않도록 `cokform.pages.dev` 내부에 둔다.
- ‘AI 티’가 나는 동일 카드·동일 그림자·과한 굵기·모노 숫자·추상 문구를 피한다.
- Discord는 파일럿 채널 하나일 뿐, 카카오·네이버·당근·파트너·자체 검색 유입으로 분산한다.
- 사용자에게 빈말을 하지 않고, 안 되는 것과 위험을 명확히 말한다.

### 이미 해결된 중요한 과거 문제

- 공개 응답 화면 공백: `PreviewForm.jsx` import 문제 수정.
- 오류 경계: 앱 전체와 공개 응답 페이지에 구현.
- Turnstile 오탐: 제거하고 honeypot/체류 시간/서버 속도 제한/정원 제한으로 변경.
- 외부 문서 라우트 누락: `/security`, `/faq` 등 확인·보완.
- 템플릿 카드 가짜 미리보기와 정적 가로 잘림: 실제 정보와 조작 가능한 캐러셀로 교체.
- 응답 데이터가 질문별 그래프와 개별 탭으로 분리된 문제: 응답자별 제출 기록으로 통합.
- 숫자 고정폭 폰트: Pretendard로 통일.

### 아직 검증하지 않은 가설

- 행사·교육·커뮤니티 운영자가 실제 신청 업무에 콕폼을 다시 사용할지.
- 템플릿·빈 캔버스·조건부 질문의 현재 진입 흐름이 3분 안에 첫 폼 완성을 돕는지.
- E2EE·키 복구 설명이 사용자에게 충분히 이해되는지.
- 한국형 브랜딩·OG 이미지가 파일럿 전환에 실제 영향을 주는지.
