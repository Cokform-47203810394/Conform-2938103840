# 콕폼 브랜드·제품 전략

## 1. 핵심 진단

현재 콕폼은 기능적으로는 폼 생성, 질문 편집, 응답 수집, 설정, 공유를 제공하지만, 사용자가 느끼는 제품 모델은 ‘Google Forms의 한국형 변형’에 가깝다. 원인은 보라색 Material 계열 색상, 중앙 카드형 질문 편집기, 질문·응답·설정 탭, 질문 유형 셀렉트, 필수 토글, 하단 질문 추가 버튼이 함께 사용되기 때문이다. 개별 기능의 문제라기보다, 시각 언어와 정보 구조가 이미 시장의 대표 제품을 연상시키는 것이 핵심 문제다.

콕폼의 차별화는 색상만 바꾸는 것으로 끝나지 않는다. 폼을 ‘문서’가 아니라 ‘사람에게서 필요한 신호를 얻는 흐름’으로 정의하고, 홈·편집·공유·답변 화면 모두에서 이 관점을 반복해야 한다.

## 2. 브랜드 포지셔닝

> **콕폼은 필요한 것을 콕 집어 묻고, 사람들의 답을 콕 집어 이해하게 하는 응답 경험 도구다.**

| 항목 | 결정 |
|---|---|
| 브랜드 약속 | 질문을 쉽게 시작하고, 응답을 자연스럽게 모으고, 결과를 빠르게 이해하게 한다. |
| 핵심 사용자 | 신청·모집·피드백·동의·참석 확인을 자주 만드는 개인, 팀, 소규모 조직 |
| 차별화된 관점 | 예쁜 문서보다 좋은 질문과 높은 응답률을 우선한다. |
| 어조 | 짧고 직접적이며 따뜻하다. 사용자를 가르치기보다 다음 행동을 제안한다. |
| 금지할 인상 | Google Forms 복제품, 행정 문서 도구, 기업용으로만 딱딱한 설문 시스템 |
| 한 줄 카피 | **필요한 답을, 콕 집어 받아요.** |
| 보조 문구 | **ASK IT WELL** |

## 3. 시각 언어

콕폼은 보라색 Material UI를 버리고, 따뜻한 아이보리 캔버스와 먹색 텍스트를 기본으로 사용한다. 그린은 신뢰와 진행 상태를, 라임은 콕폼의 포인트와 행동 유도를, 코랄은 주의·강조를 담당한다. 표면은 과도한 그림자 대신 얇은 경계선과 큰 라운드, 충분한 여백으로 구성한다.

| 역할 | 색상 | 사용 원칙 |
|---|---|---|
| Ink | `#17251F` | 제목, 핵심 텍스트, 로고 |
| Cream | `#FFFDF8` | 카드와 주요 표면 |
| Canvas | `#F5F3EC` | 전체 배경과 편집 캔버스 |
| Cok Green | `#17866D` | 주요 CTA, 활성 상태, 진행 |
| Lime Signal | `#D8ED59` | 브랜드 마크, 배지, 중요한 신호 |
| Coral | `#F28B70` | 주의, 보조 강조, 감정적 포인트 |

## 4. 화면별 원칙

| 화면 | 현재 문제 | 콕폼 방향 |
|---|---|---|
| 홈 | 문서 템플릿 갤러리와 최근 설문지 목록이 중심이다. | 목적과 상황을 먼저 제시한다. ‘무엇을 물어볼까요?’를 시작점으로 두고, 내 작업 공간은 보조 영역으로 둔다. |
| 편집기 | Google Forms와 가장 유사하다. 질문 카드·탭·유형 셀렉트가 도구 중심이다. | ‘흐름’을 만드는 캔버스로 바꾼다. 질문마다 왜 묻는지, 어떤 답을 원하는지, 응답자에게 어떻게 보이는지를 가까이 둔다. |
| 공유 | ‘게시’가 기술적인 완료처럼 느껴진다. | ‘공유 시작’으로 바꿔 실제 응답을 받는 행동을 명확히 한다. 링크·QR·응답 받기 상태를 한 패널에 모은다. |
| 답변 | 응답 수가 데이터 표에 머문다. | 응답 수, 완료율, 가장 많이 선택된 답, 자유응답 요약 등 ‘무슨 일이 일어났는가’를 먼저 보여준다. |
| 응답자 화면 | 폼을 읽고 제출하는 전형적인 구조다. | 한 번에 한 질문에 집중할 수 있는 리듬, 진행 표시, 친절한 완료 카피를 강화한다. |

## 5. 용어 체계

`질문`은 내부 데이터 모델과 호환을 위해 코드에서는 유지하되, 사용자에게 보이는 주요 내비게이션에서는 `흐름`을 사용한다. `응답`은 결과를 보는 화면에서 `답변`으로, `게시`는 `공유 시작`으로, `설문지`는 문맥에 따라 `폼`으로 바꾼다. 이 변경은 단순한 카피 수정이 아니라 제품이 무엇을 돕는지에 대한 관점 전환이다.

## 6. 기능 개선 우선순위

| 우선순위 | 개선 | 기대 효과 |
|---|---|---|
| P0 | 저장 상태를 ‘저장 중/저장됨’으로 표시 | 사용자의 불안과 데이터 손실 걱정 감소 |
| P0 | 공유 시작 패널에 링크·QR·응답 받기 상태 통합 | 게시 이후 행동이 명확해짐 |
| P0 | 템플릿을 ‘신청 받기·의견 듣기·참석 확인·동의 받기’ 목적별로 재분류 | 선택 시간이 줄고 콕폼의 관점이 드러남 |
| P1 | 질문 카드에 응답 목적 메모와 응답자 미리보기 추가 | 문서 편집기와 차별화된 질문 설계 경험 확보 |
| P1 | 답변 화면에 핵심 지표와 대표 답변을 먼저 노출 | 단순 응답 보관함에서 인사이트 화면으로 확장 |
| P1 | 응답자 화면에 진행 리듬과 완료 후 다음 행동 추가 | 이탈 감소와 브랜드 경험 강화 |
| P2 | 콕 모양 말풍선 마크, 템플릿 아트 디렉션, 아이콘 세트 정립 | 브랜드 자산의 일관성 확보 |
| P2 | 공개 폼 URL과 공유 QR의 브랜드 경험 개선 | 공유 자체가 제품 인지점이 됨 |

## 7. 이번 1차 구현 범위

이번 변경에서는 보라색 Material 토큰을 콕폼의 Ink·Cream·Green·Lime 체계로 교체하고, 홈의 시작 카피를 ‘무엇을 물어볼까요?’로 전환했다. 헤더에는 말풍선과 콕 포인트를 결합한 임시 브랜드 마크 및 `ASK IT WELL` 보조 문구를 넣었다. 편집기에서는 `질문·응답·설정`을 `흐름·답변·운영`으로 바꾸고, `게시`를 `공유 시작`, `질문 추가`를 `질문 콕 찍기`로 바꿔 제품 관점을 코드에 반영했다.

이번 변경은 기능을 제거하지 않고 제품의 표면과 언어를 먼저 바꾸는 단계다. 다음 단계에서는 질문 카드 자체를 응답 흐름 중심으로 재설계하고, 공유 패널과 답변 대시보드를 우선 구현해야 한다.
