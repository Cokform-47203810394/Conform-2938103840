# 사고 기록: 오래된 편집 초안이 폼을 덮어쓴 문제

**발생일:** 2026-08-22 KST  
**심각도:** SEV-2 — 폼 구조가 잘못된 상태로 저장됐으나, 응답과 암호화된 버전 스냅샷으로 복구 가능  
**영향 범위:** 로폴더 팀원 모집 폼 1개  
**현재 상태:** 복구 완료, 재발 방지 패치 배포 완료

## 요약

새로고침·배포 갱신 중 편집 내용을 보존하기 위해 추가한 탭 초안 복구 기능이, 초안이 어떤 서버 폼을 기준으로 만들어졌는지 검증하지 않았다. 같은 탭에 남아 있던 오래된 **1문항 초안**이 서버의 **53문항 폼**보다 우선 적용됐고, 이후 자동저장이 해당 초안을 서버에 저장했다.

폼·응답·암호화 버전은 삭제되지 않았다. 작성자 기기의 개인키로 이전 암호화 버전을 복원한 결과, 폼은 53문항으로 돌아왔고 응답 2개와 버전 기록도 유지됐다.

## 확인된 사실

| 항목 | 확인 결과 |
|---|---|
| 저장소 데이터 | 폼, 공개 폼, 응답, 버전, 워크플로 레코드가 남아 있었음 |
| 변경 전 정상 버전 | 53문항 자동저장 암호화 스냅샷 보존 |
| 잘못 저장된 현재 상태 | 1문항, 작은 폼 구조 크기 |
| 변경 요청 | 작성자 계정의 정상 인증 세션에서 `cokform.pages.dev`를 참조해 발생 |
| 외부 삭제 흔적 | 조사한 시간 범위의 DB·인증·REST 로그에서 확인되지 않음 |
| 응답 원문 | E2EE 암호문으로 보존, 복호화·변경·삭제하지 않음 |

> 이 조사 결과는 외부 침해를 증명하지 않는다는 뜻이 아니라, 현재 확보 가능한 로그에서 **외부 계정·다른 출처·폼 삭제 요청의 증거가 없었고**, 애플리케이션의 검증 없는 초안 적용 경로가 실제 원인과 일치한다는 뜻이다.

## 근본 원인

문제가 된 초안 형식은 다음 정보를 가졌다.

```text
{ version: 1, savedAt, form }
```

이 형식에는 해당 초안이 어떤 서버 원본에서 시작됐는지 보여 주는 기준선이 없었다. 편집기 시작 시 이 초안이 있으면 서버 폼보다 우선 적용됐고, 400ms 자동저장이 그대로 `forms`와 `form_public` 행을 upsert했다.

## 복구 절차

1. 최신 배포를 강력 새로고침으로 받는다.
2. 작성자 기기에서 기존 개인키 금고를 해제한다.
3. `더보기 → 버전 기록`에서 마지막 정상 자동저장본을 선택한다.
4. 복원을 확정한다. 현재 상태는 복원 전에 별도 암호화 버전으로 보관된다.
5. 서버에서 질문 수, 응답 수, 버전 수를 읽기 전용으로 확인한다.

## 전체 폼 자동복구 검사

작성자 계정의 다른 폼도 현재 질문 수와 최신·최대 암호화 버전의 질문 수를 읽기 전용으로 비교했다. 총 2개 폼 모두 현재 구조와 최신 버전이 일치했고, 로폴더 모집 폼은 복원 뒤 53문항·응답 2개·버전 49개가 확인됐다. 따라서 추가 자동복구 후보는 없었다.

자동복구는 **비정상 후보를 감지·분류**하는 데까지 자동화한다. E2EE 폼을 사용자 확인 없이 서버에서 되돌리지는 않는다. 정상적인 대규모 질문 삭제와 실제 손상을 서버가 구분할 수 없고, 버전 복호화는 작성자 기기의 개인키가 필요하기 때문이다.

## 재발 방지 수정

커밋 `53c7b67`은 초안 포맷을 버전 2로 바꾸고 서버 기준선 지문을 추가했다.

```text
{ version: 2, baseFingerprint, savedAt, form }
```

편집기를 열 때 서버 폼의 지문과 `baseFingerprint`가 같을 때만 초안을 적용한다. 다르면 초안을 폐기하고 서버 데이터를 사용한다. 구버전 1 초안은 자동 폐기한다.

## 추가 후속 조치

1. 편집 초안 호환성·서버 변경·새로고침 회귀 테스트를 정식 테스트 러너에 추가한다.
2. 서버 저장 전 질문 수 급감 등 위험 변경을 감지하는 보호 장치를 설계한다. 단, 정상적인 대규모 삭제 작업을 막지 않도록 명시적 확인·버전 복구와 함께 설계한다.
3. Supabase 보안 권고 중 유출 비밀번호 보호 설정을 별도 점검한다. 이는 Google OAuth 중심 현재 원인과 직접 관련은 없다.
4. `cokform_response_rate_limits`의 RLS 정책 없음 경고는 Edge Function 전용 테이블인지 확인하고, 필요하면 서비스 역할 전용 정책을 명시한다.
