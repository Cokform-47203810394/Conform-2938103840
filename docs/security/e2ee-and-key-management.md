# 종단간 암호화와 키 관리

Cokform은 폼 응답이 제출자의 브라우저에서 암호화되고, 폼 작성자가 자신의 개인키를 열어 복호화하는 구조를 지향합니다. 이 문서는 기능의 보안 경계와 작성자가 직접 관리해야 하는 복구 수단을 설명합니다.

## 보안 경계

| 구성 요소 | 역할 | 응답 평문 접근 |
|---|---|---|
| 응답자 브라우저 | 폼 입력, 공개키 기반 암호화, 제출 | 제출 전 입력값을 처리 |
| Cokform 웹 앱 | 폼 작성·공개 화면·복호화 도구 제공 | 개인키가 열려 있는 작성자 브라우저에서만 처리 |
| 저장소 경로 | 암호문 응답·폼 구조·운영 메타데이터 저장 | 개인키가 없으므로 암호문만 보관하도록 설계 |
| 폼 작성자 | 개인키 금고 해제, 응답 복호화·내보내기 | 자신의 복구 비밀번호와 키로 접근 |

Cokform·Supabase·Cloudflare가 복구 비밀번호를 대신 보관하거나 재설정할 수 없도록 설계되어 있습니다. 이 특성은 플랫폼의 복호화 권한을 줄이는 대신, 작성자의 키 관리 책임을 높입니다.

## 개인키 금고

폼별 개인키는 브라우저에서 암호화된 금고 형태로 보관됩니다. 금고는 복구 비밀번호를 기반으로 잠금·해제하며, 응답이나 암호화된 버전 기록을 볼 때만 해제합니다.

- 금고가 잠겨 있어도 폼 질문·운영 설정은 편집할 수 있습니다.
- 금고가 잠기면 응답 평문과 메모리상의 복호화 결과는 화면에서 제거됩니다.
- 금고를 만들지 않은 폼은 암호화 응답을 안전하게 운영할 수 없으므로, 공유 전에 키 설정을 완료하세요.

## 복구 비밀번호

복구 비밀번호는 Cokform이 알 수 없으며 재설정도 할 수 없습니다. 잊어버린 경우에 대비해 키 백업 또는 전체 복구 번들을 함께 보관해야 합니다.

### 권장 방식

1. 12자 이상이며 다른 서비스와 다른 긴 문구를 사용합니다.
2. 폼 제목·이메일·생일처럼 추측하기 쉬운 표현은 피합니다.
3. 비밀번호와 백업 파일을 같은 장소에만 두지 않습니다.
4. 팀 운영이라면 비밀번호 공유·보관 절차를 조직의 접근권한 원칙에 맞게 정합니다.

## 키 백업과 전체 복구 번들

| 도구 | 포함 대상 | 권장 사용처 |
|---|---|---|
| 암호화 키 백업 | 암호화된 개인키 금고 | 기기 교체·브라우저 초기화 대비 |
| 전체 복구 번들 | 암호화된 키 금고, 폼 구조, 암호문 응답, 버전 기록 | 저장소 장애·대규모 복구 대비 |

백업 파일은 복구 비밀번호 없이는 바로 읽을 수 없도록 암호화된 구조를 사용합니다. 그래도 백업 파일은 중요한 보안 자산입니다. 신뢰할 수 없는 메신저·공개 저장소·공유 링크에 올리지 마세요.

## 기기 교체와 복구

새 기기에서 복구하려면 다음 순서로 진행합니다.

1. Cokform에 로그인합니다.
2. 해당 폼의 `운영` 탭에서 개인키 금고를 엽니다.
3. **키 백업 가져오기** 또는 **전체 복구 가져오기**를 선택합니다.
4. 복구 비밀번호로 금고를 엽니다.
5. 답변 탭에서 필요한 응답이 복호화되는지 확인합니다.

복구 후에는 원래 기기의 세션을 잠그고, 더 이상 쓰지 않는 기기의 브라우저 데이터와 복사본을 조직 정책에 맞게 정리하세요.

## 사고 예방 점검

- 공개 링크를 공유하기 전에 개인키 금고와 백업을 준비했는지 확인합니다.
- 공개 컴퓨터에서는 금고를 열지 않습니다.
- 내보낸 CSV·Excel·JSON은 복호화된 정보일 수 있으므로 별도 접근권한으로 관리합니다.
- 답변을 볼 필요가 없을 때는 `지금 잠그기`로 금고를 잠급니다.
- 복구 비밀번호와 백업 파일을 모두 잃으면, Cokform이 응답을 대신 복호화할 수 없습니다.
