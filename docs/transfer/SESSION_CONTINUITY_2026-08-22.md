## Google OAuth / Drive 상태

Drive 연결에서 Google의 `403 access_denied`가 관찰됐다. 오류 URL에 `drive.file` 범위가 포함돼 있었으며, 이 범위는 일반 로그인 아닌 Drive 연결 요청에서만 사용한다.

현재 운영자가 수행해야 할 일은 다음과 같다.

1. Supabase의 Google Client ID가 생성된 기존 Google Cloud 프로젝트를 확인한다.
2. OAuth 동의 화면이 External·Testing이면 실제 계정을 테스트 사용자에 추가한다.
3. 동일 프로젝트에서 Google Drive API를 활성화한다.
4. `https://bnbdxcyarerrmijuvxdb.supabase.co/auth/v1/callback`이 승인된 리디렉션 URI인지 확인한다.
5. API 활성화 뒤 콕폼에서 Drive 연결 → Google Sheets 내보내기를 다시 시험한다.

> 새 Google Cloud 프로젝트를 만들었다고 해서 자동으로 전환되지는 않는다. 새 프로젝트를 사용하려면 새 OAuth Client ID·Secret을 만들고 Supabase Google 제공자 설정도 함께 바꿔야 한다.

## 보안 판단

새로고침 복구는 다음 경계를 유지한다.

- 편집 초안에는 폼 구조만 저장하며 응답 원문·개인키·복구 비밀번호를 넣지 않는다.
- 개인키는 기존과 동일하게 비밀번호 기반 금고에 암호화해 보관한다.
- 같은 탭 복구는 JWK 원문이나 비밀번호 대신 비추출형 `CryptoKey`의 세션 참조만 사용한다.
- 사용자가 `지금 잠그기`를 선택하면 탭 키 캐시도 제거한다.
- 탭·브라우저 종료, 다른 기기에서는 기존 복구 비밀번호 또는 키 백업이 필요하다.

2. 키 백업 온보딩과 다른 환경 복구를 실사용자 흐름으로 검증한다.

4. 개인정보 없는 행동 이벤트를 설계한다.
5. 실제 원문을 받지 않는 컨시어지 파일럿 3회를 진행하고 재사용 증거나 거절 이유를 기록한다.
