# 핵심 플레이북: 이 문서만 먼저 읽기

> 이 문서는 2,000개 세부 매뉴얼보다 먼저 읽는 운영 기준이다. 비밀값·개인키·응답 원문은 어떤 지원·검증·마케팅 과정에서도 받거나 기록하지 않는다.

## 1. 기능 추가를 멈추는 기준

사용자 관찰, 사용 기록, 재사용 의사가 없는 기능 요청은 백로그에만 기록하고 구현하지 않는다. 현재 콕폼은 검증 동결 상태이므로 테스트·복구·접근성·개인정보 최소화·측정 이외의 변경은 대표가 이유와 성공 기준을 문서화할 때만 재개한다.

## 2. 배포 절차

변경 전에는 `git diff --check`와 `npm run build`를 실행한다. 배포 후에는 GitHub Actions 성공 여부, 홈·폼 편집기·공개 응답 링크의 스모크 확인, 브라우저 콘솔의 새 렌더링 오류 여부를 확인한다. 실패 시 새 수정으로 덮지 말고 마지막 정상 커밋을 기준으로 원인을 분리한다.

## 3. E2EE와 복구

응답 원문은 개인키를 가진 작성자만 연다. 비밀번호를 잊어도 암호문은 보관 기간까지 남아야 하지만, 서비스가 비밀번호 재설정으로 열어주면 안 된다. 복구는 키 백업 파일·전체 복구 번들·기존 로그인 기기에서만 가능해야 한다. 개인키, 복구 비밀번호, 키 백업 파일을 지원 채널로 받지 않는다.

## 4. 응답 제한의 정직한 표현

브라우저 1회 제한은 새 브라우저 프로필과 시크릿 창에서 바뀔 수 있다. 채용·투표·경품처럼 공정성 또는 개인 식별이 필요한 폼에 ‘한 사람 1회’를 보장한다고 쓰지 않는다. 필요하면 로그인 기반, 초대 토큰, 운영자 승인 중 하나를 명시적으로 선택한다.

## 5. 컨시어지 테스트

콕폼 운영자는 실제 신청자 원문, 이력서, 연락처, 민감정보를 대신 받거나 세팅하지 않는다. 운영자의 질문 구조는 더미 데이터로 받고, 응답 원문은 그 운영자가 소유하는 폼에서만 처리한다. 첫 테스트에서는 채용·의료·금융·미성년자·민감정보 수집 폼을 제외한다.

## 6. 개인정보 없는 측정

측정 가능한 항목은 유입 출처, 템플릿 열람, 폼 생성, 첫 질문 추가, 공유 링크 생성, 재방문, 내보내기, 오류 경계 도달뿐이다. 이메일, 답변 원문, 개인키, 복구 수단은 이벤트에 넣지 않는다.

## 7. 고객지원 원칙

고객에게 복구 비밀번호·개인키·키 백업·응답 원문을 보내달라고 요청하지 않는다. 문제를 재현할 때는 폼 ID, 시각, 브라우저 버전, 오류 코드, 민감정보가 제거된 화면만 받는다.

## 8. 장애 대응 원칙

공개 응답 제출·응답 복호화·로그인 중 하나가 실패하면 먼저 새 배포를 멈추고 영향을 확인한다. 원인을 모르는 상태에서 DB, 키, 암호문을 수정하지 않는다. 사용자에게는 사실·영향·다음 확인 시각만 알리고 추측을 공지하지 않는다.

## 9. 완료 정의

구현 완료, 배포 완료, 안전 완료, 검증 완료는 다르다. 사용자가 실제 업무에 다시 사용했거나 명확한 거절 이유가 기록되기 전에는 기능이 성공한 것이 아니다.

## 10. 매뉴얼 사용법

`INDEX.csv`에서 역할·도메인·업무·상황을 찾아 해당 ID의 파일을 연다. 세부 파일은 체크리스트이며, 실제 판단 기준은 이 핵심 플레이북과 도메인별 README를 우선한다.
