# 삭제 요청 처리: 배포 직후

## 목적

암호문 응답의 보관·파기·백업과 내보내기 책임을 관리한다.

## 역할

**데이터 운영 담당자**가 실행한다. 답변 원문·개인키·복구 비밀번호가 필요한 경우에는 직접 열람하거나 전송받지 않고, 소유자가 자신의 기기에서 확인하도록 안내한다.

## 시작 조건

- `배포 직후` 상황에서 `삭제 요청 처리`가 필요해졌다.
- 이 작업의 사용자 영향, 개인정보 가능성, 되돌릴 수 있는지 여부를 먼저 확인했다.
- 새 기능 개발 요청이면 기능 동결·검증 기준을 확인했다.

## 실행 절차

1. **범위를 적는다.** 무엇을 바꾸거나 확인하는지, 대상 폼·화면·기간을 한 문장으로 기록한다.
2. **민감도를 분류한다.** 답변 원문, 이메일, 개인키, 복구수단, 접근 권한이 포함되면 해당 값을 복사·전송하지 않는다.
3. **현재 상태를 확인한다.** 운영 화면, 저장소의 최신 커밋, 관련 설정 또는 기록을 읽고 추측으로 실행하지 않는다.
4. **가장 작은 안전한 조치를 한다.** 변경은 한 번에 하나만 적용하고, 되돌릴 방법을 확인한다.
5. **영향을 확인한다.** 사용자 핵심 경로 또는 해당 운영 지표가 예상대로 동작하는지 점검한다.
6. **기록한다.** 아래 기록 항목과 완료 조건을 채우고, 예상과 다르면 다음 단계로 넘어가지 않는다.

## 판단 기준

| 상황 | 행동 |
|---|---|
| 답변 원문·개인키·복구 비밀번호가 필요해 보임 | 중단하고 `SEC` 또는 `SUP` 매뉴얼로 이동 |
| 배포·삭제·권한 변경이 필요한데 롤백이 없음 | 중단하고 `OPS` 또는 `DAT` 매뉴얼로 이동 |
