# Cokform 닫힘 UX QA 기록 — 2026-08-19

## 검증 범위

작성자와 홈 화면에서 열리는 보조 패널·대화상자의 닫힘 경험을 점검했다. 목표는 사용자가 다른 곳을 누르거나 `Esc`를 눌렀을 때 현재 맥락을 유지한 채 열린 UI만 즉시 닫는 것이다.

| 화면·요소 | 바깥 클릭 | Esc | 결과 |
|---|---:|---:|---|
| 편집기 데스크톱 테마 팝오버 | 통과 | 공용 처리 적용 | 통과 |
| 홈 응답 알림 패널 | 통과 | 통과 | 통과 |
| 홈 검색 자동완성 | 공용 문서 클릭 처리 적용 | 통과 | 통과 |
| 공용 모달(공유·삭제·버전·키 금고 등) | 기존 바깥 클릭 유지 | 공용 처리 적용 | 통과 |
| 편집기 모바일 테마 패널 | 투명 바깥 클릭 레이어 적용 | 통과 | 통과 |

## 모바일 점검

실제 Chromium 세션을 390×844 CSS px(2× DPR)로 전환해 홈의 알림 패널을 검사했다. 패널은 바깥 클릭과 `Esc` 모두에서 열린 상태에서 정상적으로 닫혔다. 닫힌 뒤 홈 상단, 검색 영역, 가로 스크롤 템플릿 카드, 하단 영역의 잘림·중첩은 발견하지 못했다.

## 테스트 산출물 정리

바깥 클릭 검증 중 실수로 생성된 `사내 의견 수렴` 템플릿은 사용자의 확인 뒤 삭제했다. 해당 폼은 삭제 직전 조회 0건·응답 0건이었으며, 기존 `채용 지원서`와 응답 2건은 그대로 유지됐다.

## 남은 UX 원칙

새로운 드롭다운·팝오버를 추가할 때는 공용 `Popover` 또는 문서 수준의 바깥 클릭/`Esc` 처리 중 하나를 반드시 사용한다. 작업 중인 폼의 제목·문항을 바꾸는 클릭은 패널을 닫는 동작과 분리해, 사용자가 클릭 한 번으로 의도치 않은 편집이나 화면 이동을 하지 않도록 유지한다.
